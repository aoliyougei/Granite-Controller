# OpenAI Managed VM Start v0.3.0 — Design Specification

**Date:** 2026-09-08  
**Status:** Approved in discussion; awaiting written-spec review  
**Target release:** `v0.3.0`

## 1. Purpose

Extend the embedded Needle 2 service with one managed, automatically executed infrastructure action while retaining an OpenAI Chat Completions request/response surface. A client or Agent sends a normal OpenAI request containing a Chinese instruction such as `开启 VM 3052`; it does not need to supply a usable tool definition. The server extracts only the current user instruction, safely normalizes it, requires the embedded Needle 2 model to select the built-in `pve_vm_start` tool, validates the model result, calls Infrastructure Control once, and returns a synthesized Chinese OpenAI assistant response.

Needle 2 remains a mandatory semantic tool selector. Chinese rules never directly authorize or execute the action.

## 2. Goals

- Keep the v0.2.0 single-image, single-Go-process, embedded Needle Engine 2.0.3 architecture.
- Keep `GET /v1/models` and `POST /v1/chat/completions` with `NEEDLE_API_KEY` authentication.
- Accept requests generated by Agent clients even when they include system prompts, history, tools, and tool choice.
- Process only the final message when it is a non-empty, plain-text `role: "user"` message.
- Ignore all earlier messages and every client-provided tool/tool-choice field.
- Always present exactly one built-in `pve_vm_start` schema to Needle 2.
- Require Needle 2 to return exactly one matching tool call and VM ID.
- Apply confidence, grounding, and negation safety gates before execution.
- Execute exactly one fixed Infrastructure Control VM-start endpoint with environment-provided credentials.
- Never retry an infrastructure mutation automatically.
- Return ordinary and synthesized-streaming OpenAI assistant responses containing a Chinese final status.

## 3. Non-goals

- Dynamic client-provided tools.
- Returning `tool_calls` for client execution.
- Supporting any managed tool other than PVE VM start.
- VM status, shutdown, stop, reboot, PVE node, host, power, PBS, workflow, task, log, or event operations.
- General Chinese translation or open-ended chat.
- Multi-turn semantic context, assistant history, tool-result replay, or system prompt execution.
- Server-side sessions.
- Confirmation workflows, VM allowlists, role-based authorization, or persistent audit storage in v0.3.0.
- Automatic retry of Needle inference or Infrastructure Control mutation calls.
- Claiming that Infrastructure Control HTTP 202 means VM startup is complete.

## 4. Version and Compatibility

Target version is `v0.3.0` because the meaning of `/v1/chat/completions` changes materially from v0.2.0:

- v0.2.0: client supplies dynamic tools; server returns tool calls and never executes.
- v0.3.0: client tools/history are ignored; server uses one internal tool, executes it, and returns final assistant text.

The immutable `v0.2.0` tag remains available for general OpenAI tool selection. The immutable `v0.1.1` tag remains available for the earlier `/api/v1/chat` PVE controller.

## 5. Public API

### 5.1 Endpoints

```http
GET  /healthz
GET  /readyz
GET  /v1/models
POST /v1/chat/completions
```

`/healthz` and `/readyz` remain public. `/v1/*` requires:

```http
Authorization: Bearer <NEEDLE_API_KEY>
```

### 5.2 Minimal request

```json
{
  "model": "needle-2",
  "messages": [
    {"role": "user", "content": "开启 VM 3052"}
  ]
}
```

### 5.3 Agent-style request

The following is accepted:

```json
{
  "model": "needle-2",
  "messages": [
    {"role": "system", "content": "You are an infrastructure assistant."},
    {"role": "user", "content": "查询 VM 3052"},
    {"role": "assistant", "content": "Previous answer"},
    {"role": "tool", "tool_call_id": "old-call", "content": "old result"},
    {"role": "user", "content": "开启 VM 3053"}
  ],
  "tools": [
    {"type":"function","function":{"name":"agent_private_tool","parameters":{"type":"object"}}}
  ],
  "tool_choice": "required"
}
```

Only `开启 VM 3053` is processed. The earlier VM ID, system instructions, assistant/tool history, client tools, and client tool choice do not reach Needle and cannot affect execution.

### 5.4 Final-message rule

The server inspects only `messages[len(messages)-1]`.

It must be:

- `role: "user"`;
- content encoded as one JSON string;
- non-empty after trimming;
- within the configured message-length limit.

The server does not search backward for another user message. If the final message is system/developer/assistant/tool, empty, `null`, content parts, image/audio/file data, or any non-string content, the request fails with OpenAI HTTP 400:

```json
{
  "error": {
    "message": "A non-empty final user text message is required.",
    "type": "invalid_request_error",
    "param": "messages",
    "code": "user_message_required"
  }
}
```

This fail-closed rule prevents a stale historical user command from being executed.

### 5.5 Ignored Agent fields

The request parser remains permissive for OpenAI compatibility. It accepts but does not use:

- earlier messages of every role, including earlier user messages;
- `tools`;
- `tool_choice`;
- system/developer instructions;
- assistant/tool/function history;
- `response_format`;
- sampling parameters;
- unknown top-level fields.

Ignored fields produce stable `x_needle.warnings`, without including their content:

- `earlier messages were ignored; only the final user message is processed`
- `client-provided tools were ignored; the managed tool catalog is fixed`
- `tool_choice was ignored; the managed tool catalog is fixed`
- relevant sampling/response-format warnings.

Client-provided tools never return `client_tools_not_supported` and never enter native schema compilation.

## 6. Managed Tool

The only internal tool is:

```json
{
  "name": "pve_vm_start",
  "description": "Start a Proxmox VE virtual machine",
  "parameters": {
    "type": "object",
    "properties": {
      "vmid": {
        "type": "integer",
        "description": "Numeric Proxmox VE virtual machine ID"
      }
    },
    "required": ["vmid"],
    "additionalProperties": false
  }
}
```

This catalog is compiled into Go source or an embedded, version-controlled JSON file. It is not supplied by clients and is not loaded from a mutable remote source.

The fixed execution mapping is:

```http
POST {INFRA_CONTROL_API_BASE_URL}/api/v1/pve/vms/{vmid}/start
Authorization: Bearer <INFRA_CONTROL_API_TOKEN>
Accept: application/json
```

No generic method/path executor exists.

## 7. Chinese Input Gate and Normalization

### 7.1 Supported intent

The final message must contain:

- at least one Chinese Han character;
- an explicit VM marker: standalone case-insensitive `VM` or `虚拟机`;
- one supported start phrase: `开启`, `启动`, `开机`, `打开`, or `开起来`;
- exactly one ASCII decimal integer VM ID;
- a VM ID greater than zero and representable as signed 64-bit integer.

### 7.2 Rejected intent

Reject before Needle inference if the final message contains a conflicting or negative phrase including:

- `不要`
- `别`
- `禁止`
- `无需`
- `取消`
- `关闭`
- `关机`
- `停止`
- `重启`
- `重新启动`

Reject multiple numeric IDs, no ID, zero/negative/overflow ID, English-only requests, ambiguous VM-like terms such as `VMware`, unsupported operations, or missing explicit VM semantics.

### 7.3 Normalized model input

A valid instruction becomes exactly:

```text
Start VM <vmid>
```

Example:

```text
开启 VM 3052 -> Start VM 3052
```

The original and normalized values are kept separately. Only the normalized text is sent to Needle; the original VM ID is retained for cross-validation.

### 7.4 Mandatory model decision

Rules never call Infrastructure Control directly. The sequence is always:

```text
validate/normalize Chinese input
-> native Dispatcher
-> needle_reset
-> needle_init with built-in pve_vm_start
-> needle_complete("Start VM <vmid>")
-> validate Needle result
-> execute Infrastructure Control
```

If Needle is not ready or fails, no upstream action occurs.

## 8. Needle Result Safety Gate

All conditions must hold:

1. Native response `success` is true.
2. Native response type is `call`.
3. Exactly one function call exists.
4. Function name is exactly `pve_vm_start`.
5. Arguments contain exactly one key, `vmid`.
6. `vmid` is a positive JSON integer.
7. Model VM ID exactly equals the VM ID parsed from the original Chinese final message.
8. `confidence` is present, finite, within `[0,1]`, and at least `NEEDLE_MIN_CONFIDENCE`.
9. `validation.ungrounded` is present and empty.
10. `validation.negation` is false.

Any failure returns an OpenAI error and guarantees that Infrastructure Control was not called.

`NEEDLE_MIN_CONFIDENCE` defaults to `0.6` and may be changed through environment configuration.

## 9. Infrastructure Control Client

### 9.1 Configuration

Use the existing environment names exactly:

```text
INFRA_CONTROL_API_BASE_URL
INFRA_CONTROL_API_TOKEN
INFRA_CONTROL_TIMEOUT=30s
```

All three effective values are required except that timeout has the default above. There is no fallback to `INFRA_CONTROL_BASE_URL`.

### 9.2 URL validation

`INFRA_CONTROL_API_BASE_URL` must be an HTTP(S) origin:

- scheme `http` or `https`;
- non-empty host;
- no userinfo;
- no query;
- no fragment;
- no non-root path.

Trailing slashes are normalized away.

### 9.3 Mutation behavior

For a validated VM ID, send exactly one POST to the fixed path. Disable redirects. Bound response bodies. Do not log credentials or unrestricted response bodies.

Do not retry on:

- connection failure;
- timeout;
- response loss;
- HTTP 401/403;
- HTTP 429;
- HTTP 5xx;
- any non-202 response.

Only HTTP 202 is success. Because a response can be lost after upstream acceptance, errors must state that execution status may be unknown and callers should query VM status before repeating the command.

## 10. OpenAI Success Response

### 10.1 Non-streaming

After Infrastructure Control returns 202:

```json
{
  "id": "chatcmpl-...",
  "object": "chat.completion",
  "created": 1788830000,
  "model": "needle-2",
  "choices": [{
    "index": 0,
    "message": {
      "role": "assistant",
      "content": "VM 3052 的启动请求已提交。"
    },
    "finish_reason": "stop"
  }],
  "usage": {
    "prompt_tokens": 0,
    "completion_tokens": 0,
    "total_tokens": 0,
    "estimated": true
  },
  "x_needle": {
    "type": "call",
    "tool": "pve_vm_start",
    "arguments": {"vmid": 3052},
    "confidence": 0.97,
    "validation": {"ungrounded": [], "negation": false},
    "executed": true,
    "upstream_status": 202,
    "warnings": []
  }
}
```

No `tool_calls` are returned after server-side execution, preventing an Agent from executing the action a second time.

The text says `启动请求已提交`, not `VM 已启动`, because HTTP 202 does not represent final device state.

### 10.2 Synthesized SSE

For `stream: true`, the service waits until Needle validation and upstream execution complete, then emits:

1. assistant role delta;
2. one Chinese content delta;
3. terminal `finish_reason: "stop"` with `x_needle`;
4. optional usage chunk when requested;
5. `data: [DONE]`.

No tool-call delta is emitted because the managed tool has already executed. Streaming remains synthesized and does not improve time to first byte.

If the client disconnects before upstream execution begins, context cancellation prevents execution where possible. Once the POST is sent, disconnect cannot revoke it. No retry occurs.

## 11. OpenAI Errors

All errors use the existing OpenAI envelope.

Core mappings:

| Condition | HTTP | Code |
|---|---:|---|
| Missing/wrong API key | 401 | `invalid_api_key` |
| Unsupported model | 404 | `model_not_found` |
| Missing/invalid final user text | 400 | `user_message_required` |
| Invalid/negative/ambiguous Chinese command | 400 | `unsupported_managed_command` |
| Model loading/failed | 503 | `model_not_ready` |
| Native queue full | 429 | `engine_busy` |
| Native engine failure | 502 | `engine_error` |
| No/multiple/wrong model call | 422 | `managed_tool_validation_failed` |
| Low confidence | 422 | `low_confidence` |
| Ungrounded arguments | 422 | `ungrounded_arguments` |
| Model/original VM ID mismatch | 422 | `argument_mismatch` |
| Infrastructure auth failure | 502 | `upstream_auth_failed` |
| Infrastructure timeout | 504 | `upstream_timeout` |
| Other non-202/connection error | 502 | `upstream_request_failed` |

Errors do not include tokens, native buffers, unrestricted upstream responses, or ignored client content.

## 12. Configuration

Retain v0.2.0 native settings and add:

| Variable | Required | Default | Purpose |
|---|---:|---|---|
| `NEEDLE_API_KEY` | yes | — | Bearer auth for `/v1/*`. |
| `NEEDLE_MODEL_ID` | no | `needle-2` | Accepted/advertised model. |
| `NEEDLE_MIN_CONFIDENCE` | no | `0.6` | Managed execution gate. |
| `NEEDLE_MAX_MESSAGE_LENGTH` | no | `512` | Final user message character limit. |
| `NEEDLE_MAX_NEW_TOKENS` | no | `256` | Native generation budget. |
| `NEEDLE_MAX_QUEUE_DEPTH` | no | `32` | Native queue capacity. |
| `NEEDLE_BUFFER_SIZE` | no | `1048576` | Native output buffer. |
| `NEEDLE_TOOL_INDEX_PATH` | no | empty | Optional native index path. |
| `NEEDLE_ENGINE_SLOW_CALL` | no | `30s` | Slow-call warning threshold. |
| `INFRA_CONTROL_API_BASE_URL` | yes | — | Infrastructure Control origin. |
| `INFRA_CONTROL_API_TOKEN` | yes | — | Upstream Bearer credential. |
| `INFRA_CONTROL_TIMEOUT` | no | `30s` | One upstream request timeout. |

`NEEDLE_MAX_REPLAY_STEPS` may be removed because only one final user turn is submitted to Needle. If retained for compatibility, it has no behavioral effect and must be documented as deprecated; removal is preferred in v0.3.0.

## 13. Health and Readiness

`/healthz` remains process liveness.

`/readyz` should require both:

- embedded Needle model state `ready`;
- valid required startup configuration.

Whether temporary Infrastructure Control unavailability affects readiness is intentionally not checked through an active downstream request: startup validates configuration syntax, while execution reports live upstream errors. This avoids making every readiness probe call Infrastructure Control.

## 14. Logging and Request IDs

- Preserve/generate `X-Request-ID`.
- Propagate it to Infrastructure Control.
- Log request ID, normalized managed operation name, validated VM ID, confidence, upstream status, and duration.
- Do not log authorization headers, API tokens, full historical messages, ignored tools, full native buffers, or unrestricted upstream bodies.
- Log ignored-field categories, not ignored content.

## 15. Internal Structure

Recommended additions/replacements:

```text
internal/managed/
├── input.go             # final-user extraction and warnings
├── normalize.go         # strict Chinese VM-start gate
├── tool.go              # fixed Needle schema
├── validate.go          # model result safety gate
├── service.go           # model -> validate -> execute -> final response
└── streaming.go         # final-content SSE

internal/infracontrol/
├── client.go            # fixed StartVM method
└── models.go
```

Reuse:

- `internal/native/` embedded engine and Dispatcher;
- OpenAI error/model/ID/usage primitives where suitable;
- authentication and request-ID middleware.

Remove from active request flow:

- dynamic tool/schema validation;
- multi-turn replay;
- tool-call response mapping.

These generic v0.2.0 components may be deleted if no longer used; do not retain speculative dual-mode support.

## 16. Testing Strategy

All project execution remains Docker-only and follows TDD.

### 16.1 Agent input tests

- Minimal final user message accepted.
- Earlier user IDs ignored.
- system/developer/assistant/tool/function history ignored.
- client tools/tool choice ignored, never validated or executed.
- stable category warnings returned.
- final non-user message fails without searching backward.
- final empty/null/content-parts/image/audio/object message fails.
- unknown top-level fields remain compatible.

### 16.2 Chinese normalization tests

Accept:

```text
开启 3052 这个 VM
启动虚拟机 3052
把 VM 3052 开起来
给 3052 号虚拟机开机
打开 VM 3052
```

Reject:

```text
不要开启 VM 3052
别启动虚拟机 3052
禁止打开 VM 3052
取消启动 VM 3052
关闭 VM 3052
重启 VM 3052
重新启动 VM 3052
启动 VM 3052 和 3053
开启 VMware 3052
开启 VM
开启 VM 0
English-only input
```

### 16.3 Mandatory model-decision tests

- Valid normalization always calls Dispatcher once.
- No rule-only execution path exists.
- Model no-call/multiple-call/wrong-call rejects without upstream call.
- Invalid/extra/string/fractional/zero/negative VM ID rejects.
- Model/original ID mismatch rejects.
- Missing/NaN/out-of-range/low confidence rejects.
- Missing/non-empty ungrounded rejects.
- Negation rejects.

### 16.4 Infrastructure client tests

- Exactly one fixed POST path.
- Correct Bearer token and request ID.
- Redirect rejected.
- Only 202 accepted.
- No retries for every failure class.
- Timeout/auth/general error mappings.
- Bounded/sanitized response parsing.

### 16.5 Service orchestration tests

- Exact order: extract final user -> normalize -> Needle -> validate -> upstream -> response.
- Every pre-upstream failure makes zero upstream calls.
- Successful request makes exactly one upstream call.
- Disconnect before queue execution prevents action.
- Disconnect after POST does not retry.
- Final response contains no `tool_calls`.

### 16.6 HTTP and SSE tests

- Agent-style request with tools/history succeeds based only on final user.
- OpenAI authentication/model/error envelopes.
- Ordinary synthesized Chinese final response.
- SSE role/content/finish/x_needle/usage/DONE.
- No SSE tool-call delta.
- `/v1/models`, `/healthz`, `/readyz` remain correct.

### 16.7 Real end-to-end test

With explicit authorization and test credentials:

```text
OpenAI request final user: 打开 VM 3052
-> managed normalizer: Start VM 3052
-> embedded real Needle 2: pve_vm_start({"vmid":3052})
-> safety gate passes
-> real POST /api/v1/pve/vms/3052/start returns 202
-> VM state query changes stopped -> running
-> OpenAI assistant content reports request submitted
```

Record before/after state and remove temporary credentials/containers. Do not automatically stop the VM unless separately authorized.

## 17. Documentation and Release

README and CHANGELOG must state:

- v0.3.0 is managed auto-execution, not general dynamic tool calling;
- only `pve_vm_start` is available;
- client tools and history are ignored;
- only the final plain-text user message is processed;
- Needle 2 remains mandatory for semantic selection;
- credentials and upstream execution responsibility moved back into the server;
- no automatic retries;
- streaming begins only after action completion;
- use v0.2.0 for general client-provided tools.

Before release:

```text
CGO_ENABLED=0 go test ./...
go test -race ./...
go vet ./...
go test -tags=needle_native ./internal/native ...
```

Build and verify a non-root/read-only image, then run controlled and authorized real end-to-end testing. Publishing `v0.3.0` and its image requires a separate explicit release request.

## 18. Acceptance Criteria

v0.3.0 is ready when:

1. A client can send only standard OpenAI `model` and `messages` containing final user text `开启 VM 3052`.
2. Agent-added system/history/tools/tool-choice content neither fails the request nor affects execution.
3. Only the final message is considered, and it must be non-empty plain-text user content.
4. Strict Chinese rules normalize but never directly execute.
5. Embedded Needle 2 is invoked and must select exactly `pve_vm_start` with the matching VM ID.
6. Confidence/grounding/negation gates pass before execution.
7. The server reads `INFRA_CONTROL_API_BASE_URL` and `INFRA_CONTROL_API_TOKEN` only for the fixed upstream call.
8. Exactly one POST is made and no failure is retried.
9. HTTP 202 returns OpenAI assistant text `VM <id> 的启动请求已提交。` with no `tool_calls`.
10. Synthesized SSE returns role, Chinese content, stop metadata, optional usage, and DONE after execution.
11. Every rejection guarantees zero upstream calls.
12. A real authorized Chinese test proves stopped -> running through the embedded Needle model and upstream API.
13. v0.2.0 and v0.1.1 remain immutable and available for their prior behaviors.
